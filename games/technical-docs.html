🔧 Technical Documentation

Games Collection Architecture & Implementation

Built with: Cursor IDE + Claude/Grok LLMs | Stack: HTML5/CSS3/ES6+ | Paradigm: Progressive Enhancement

Development Environment

  • IDE: Cursor (VS Code fork with AI integration)
  • Version Control: Git with GitHub
  • Deployment: Local Python HTTP server + manual file serving
  • Testing: Browser dev tools + manual QA
  • Documentation: Markdown files + inline code comments

Core Technologies

  • Frontend: Vanilla HTML5/CSS3/ES6+
  • Backend: Python FastAPI + WebSocket servers
  • AI Engines: Stockfish (Chess), YaneuraOu (Shogi), KataGo (Go)
  • Database: JSON files + localStorage (client-side)
  • Real-time: WebSocket connections for multiplayer

Standards & Best Practices

  • HTML: Semantic markup, accessibility (WCAG 2.1)
  • CSS: BEM methodology, CSS Grid/Flexbox, mobile-first
  • JavaScript: ES6+ features, modular architecture
  • Performance: Code splitting, lazy loading, efficient rendering
  • Security: Input sanitization, CORS policies, secure defaults

Architecture Patterns

  • Component-based: Modular HTML/CSS/JS per game
  • Event-driven: DOM events + custom event system
  • MVC-like: Separation of game logic, rendering, and input
  • Progressive Enhancement: Works without JavaScript
  • Mobile-first: Responsive design with touch optimization

🎯 Development Philosophy

Progressive Enhancement: Every game works without JavaScript, then enhances with it.
Mobile-First: Designed for touch devices, enhanced for desktop.
Accessibility: WCAG 2.1 compliant, keyboard navigation, screen reader support.
Performance: Lazy loading, efficient rendering, minimal dependencies.
