Development Workflow

The development process follows an iterative AI-human collaboration model with rapid prototyping, testing, and refinement cycles.

1

Requirements Analysis

Human defines feature requirements and user experience goals. AI analyzes technical feasibility and suggests implementation approaches.

2

AI Implementation

Primary AI (Claude) generates initial code, implements algorithms, and creates the core functionality using Cursor IDE.

3

AI Debugging

Secondary AI (Grok) reviews code for bugs, performance issues, and cross-browser compatibility problems.

4

Human Testing

Manual testing across devices, identification of UX issues, and validation of game mechanics and responsiveness.

5

Iterative Refinement

Human feedback drives AI improvements. Code is refactored, optimized, and enhanced based on testing results.

6

Documentation

AI generates technical documentation, updates README files, and creates comprehensive code comments.

7

Git Integration

Changes committed with descriptive messages, pushed to GitHub, and integrated into the main codebase.

Deployment & Hosting

Local Development Server:
python -m http.server 9876
# Simple HTTP server for static files
# No build process required
# Hot reload via browser refresh
Backend Services:
# AI Engines (separate processes)
python stockfish-server.py # Chess AI
python shogi-server.py # Shogi AI
python go-server.py # Go AI
python multiplayer-server.py # WebSocket server
PowerShell Automation:
# START_SERVERS_RESILIENT.ps1
# - Starts all backend services
# - Monitors for failures
# - Automatic restart on crashes
# - Parallel execution for speed

Code Organization

Directory Structure:
ai-games-collection/
├── *.html # Game pages
├── js/ # Shared JavaScript
│ ├── device-adaptive.js # Responsive system
│ ├── achievements.js # Achievement system
│ └── unified-multiplayer.js
├── styles.css # Global styles
├── technical-docs*.html # Documentation
├── ai-games-collection-mcp/ # MCP server
└── *-server.py # Backend services
File Naming Conventions:
• kebab-case for HTML files (tetris.html)
• camelCase for JavaScript functions/variables
• PascalCase for classes (DeviceAdaptive)
• snake_case for Python files (stockfish_server.py)
• Descriptive, consistent naming throughout

Version Control Strategy

Git Workflow:
# Feature branches for development
git checkout -b feature/large-scrollable-board

# Atomic commits with descriptive messages
git commit -m "feat: implement large scrollable board for Ticket to Ride

- Add 1200x800px board with overflow scrolling
- Reduce route lines to 2-3px for cleaner appearance
- Update device adaptive system for large maps
- Mobile responsive adjustments"

# Regular pushes to track progress
git push origin feature/large-scrollable-board
Commit Message Format:
type(scope): description

feat: new feature
fix: bug fix
docs: documentation
style: formatting
refactor: code restructuring
perf: performance improvement
test: testing
chore: maintenance
