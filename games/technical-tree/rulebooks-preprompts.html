📚 Rulebooks & Preprompts Guide

Essential setup for consistent, high-quality AI collaboration

🎯 Why Rulebooks Matter

Rulebooks ensure AI understands your context from the start:

  • Coding standards and conventions
  • Project-specific requirements and constraints
  • Your preferred workflows and patterns
  • Quality expectations and testing standards
  • Domain-specific knowledge and terminology

Without rulebooks, AI starts from scratch every conversation. With rulebooks, AI becomes your knowledgeable partner.

📁 File Locations

  • Antigravity/Gemini: ~/gemini.md (home directory)
  • Cursor IDE: .cursorrules (project root)
  • Claude Desktop: Can reference external rulebooks or use inline instructions

📝 Cursor .cursorrules Template

Create .cursorrules in your project root:

# Project Rules for [Your Project Name] ## Core Principles - [List your project's core principles] - [Quality standards you maintain] - [Architecture patterns you follow] ## Coding Standards - [Language-specific conventions] - [Naming conventions] - [Code organization patterns] - [Testing requirements] ## Project Context - [What this project does] - [Key technologies and frameworks] - [Important constraints or requirements] - [Domain-specific knowledge] ## Communication Style - [How you prefer AI to communicate] - [Level of detail expected] - [When to ask for clarification vs. making assumptions] ## Quality Checks - [What to validate before suggesting changes] - [Testing requirements] - [Performance considerations] - [Security requirements]

💡 Pro Tips for .cursorrules

  • Keep it concise but comprehensive (200-500 words)
  • Update it as your project evolves
  • Include specific examples of good vs. bad patterns
  • Mention any unusual dependencies or constraints

🤖 Antigravity Gemini.md Template

Create ~/gemini.md in your home directory:

# Gemini AI Assistant Rules ## My Identity & Preferences - I am a [your role/profession] who [brief description of your work style] - I prefer [concise/detailed] explanations with [practical/theoretical] focus - I work on [types of projects you typically do] ## Coding Philosophy - [Your approach to code quality, testing, documentation] - [Preferred frameworks, languages, tools] - [Code organization principles you follow] ## Communication Preferences - [How you like AI to structure responses] - [When to provide code examples vs. explanations] - [How detailed you want planning discussions to be] ## Quality Standards - [Your requirements for code reviews, testing, documentation] - [Performance and security considerations] - [Maintenance and scalability requirements] ## Workflow Preferences - [How you like to break down complex tasks] - [Your iteration and feedback preferences] - [When you want AI to take initiative vs. ask for permission] ## Domain Knowledge - [Specific domains you work in] - [Industry-specific requirements or regulations] - [Technical specialties or interests] ## Boundaries & Ethics - [What AI should/shouldn't suggest] - [Ethical considerations in your work] - [Privacy or security requirements]

💡 Pro Tips for Gemini.md

  • Make it personal - this file represents YOU to AI assistants
  • Include specific examples of your work style
  • Update it regularly as your preferences evolve
  • Use it across different AI tools that support rulebooks

🎭 Preprompt Engineering

Effective Preprompt Structure

You are [role/persona], an expert [domain]. Context: [Brief project/product description] Goal: [What we're trying to achieve] Constraints: [Important limitations or requirements] Style: [How you want responses structured] [Specific task or question]

🎯 Preprompt Categories

Planning Preprompts

You are a senior software architect. I need to plan [project/feature]. Current state: [What exists] Requirements: [What needs to be built] Constraints: [Time, budget, tech limitations] Stakeholders: [Who will use/maintain this] Provide a detailed technical plan with: 1. High-level architecture 2. Key components and interactions 3. Implementation phases 4. Risk assessment 5. Success metrics

Implementation Preprompts

You are an expert [language/framework] developer. I need to implement [specific feature]. Existing code: [Relevant code snippets] Requirements: [Functional requirements] Best practices: [Follow these patterns] Testing: [How this should be tested] Provide: 1. Complete implementation 2. Unit tests 3. Integration points 4. Error handling 5. Documentation

Review Preprompts

You are a senior code reviewer. Review this [code/feature/plan]. Standards: [Quality criteria] Context: [How this fits into larger system] Risks: [What could go wrong] Provide: 1. Overall assessment 2. Specific issues found 3. Improvement suggestions 4. Security considerations 5. Performance implications

🔄 Rulebook Maintenance

Regular Updates

  • Monthly Review: Do your rulebooks still reflect your current preferences?
  • Project Changes: Update when switching technologies or methodologies
  • AI Evolution: Adjust as you learn better ways to work with AI
  • Team Alignment: Ensure consistency across team members if applicable

Version Control

Keep rulebooks in git:

  • Track evolution of your AI collaboration preferences
  • Share effective rulebooks with others
  • Revert if experiments don't work well
  • Document what works for different types of projects

Testing Rulebooks

  • A/B Testing: Try different rulebook versions on similar tasks
  • Feedback Loop: Note what works well vs. what causes issues
  • Iterative Improvement: Refine based on actual collaboration results
  • Context-Specific: Different rulebooks for different project types

🚀 Getting Started

Start with the templates above, customize them for your needs, and iterate based on your experience. Good rulebooks evolve with you - they're living documents that improve your AI collaboration over time.
